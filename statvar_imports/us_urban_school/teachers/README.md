# US_Urban_Schools_Teachers_And_Staff Import

This import focuses on data about full-time equivalent (FTE) teachers and staff in urban schools across the United States.

-----

## 📊 Dataset Coverage

- **Source**: U.S. Department of Education, Civil Rights Data Collection (CRDC)
- **Provenance URL**: [https://civilrightsdata.ed.gov/data](https://civilrightsdata.ed.gov/data)
- **Geographic Entities**: Public schools across the United States identified by NCES School IDs (`nces/...`).
- **Temporal Scope**: Biennial data covering school years 2009-10 (2010), 2011-12 (2012), 2013-14 (2014), 2015-16 (2016), 2017-18 (2018), 2020-21 (2021), and 2021-22 (2022). Future releases are automatically supported.
- **Statistical Variables**: Number of Full-Time Equivalent (FTE) teachers and school staff (Total FTE teachers, certified teachers, uncertified teachers, school counselors, nurses, psychologists, social workers, and security staff / law enforcement officers).

-----

## ⚙️ Workflow

The workflow for this data import involves two main steps: downloading the necessary files and then processing them.

### Step 1: Download the Source Data

To acquire the necessary data files, execute the download script `../download.py` from the `teachers/` directory:

```bash
python3 ../download.py --data_type=teachers
```

All downloaded raw files (XLSX and CSV formats) will be stored in `input_files/`.

-----

### Step 2: Process the Files

After successfully downloading the files, run the processing script to generate the final output artifacts. There are two ways to do this:

#### Option A: Use the `run.sh` script (Recommended)

The `run.sh` script automates the processing of all the downloaded files and emits counter metrics:

```bash
bash run.sh
```

#### Option B: Manually Execute the Processing Script

The final output is generated by processing the downloaded data using the `stat_var_processor.py` script located in `tools/statvar_importer/`:

##### --- 1. Process 2010, 2012, and 2014 Files (Older XLSX format) ---
```bash
python3 ../../../tools/statvar_importer/stat_var_processor.py \
  --input_data="input_files/2010_Teachers.xlsx,input_files/2012_Teachers.xlsx,input_files/2014_Teachers.xlsx" \
  --pv_map=teachers_and_staff_pvmap.csv \
  --config_file=metadata.csv \
  --existing_statvar_mcf=gs://unresolved_mcf/scripts/statvar/stat_vars.mcf \
  --output_path=output_files/teachers_and_staff_2010_2014_output \
  --output_counters=counters/teachers_and_staff_2010_2014_counters.csv \
  --log_level=-2 \
  --log_every_n=1000
```

##### --- 2. Process 2016 File (Separate CSV) ---
```bash
python3 ../../../tools/statvar_importer/stat_var_processor.py \
  --input_data=input_files/2016_Teachers.csv \
  --pv_map=teachers_and_staff_pvmap.csv \
  --config_file=metadata.csv \
  --existing_statvar_mcf=gs://unresolved_mcf/scripts/statvar/stat_vars.mcf \
  --output_path=output_files/teachers_and_staff_2016_output \
  --output_counters=counters/teachers_and_staff_2016_counters.csv \
  --log_level=-2 \
  --log_every_n=1000
```

##### --- 3. Process 2018 onwards Files (Combined CSVs, excluding 2016) ---
```bash
CSV_FILES_2018_ONWARD=$(find input_files -maxdepth 1 -name "*.csv" | grep -v "2016_Teachers.csv" | sort | paste -sd, -)

python3 ../../../tools/statvar_importer/stat_var_processor.py \
  --input_data="$CSV_FILES_2018_ONWARD" \
  --pv_map=teachers_and_staff_pvmap.csv \
  --config_file=metadata.csv \
  --existing_statvar_mcf=gs://unresolved_mcf/scripts/statvar/stat_vars.mcf \
  --output_path=output_files/teachers_and_staff_2018_2022_output \
  --output_counters=counters/teachers_and_staff_2018_2022_counters.csv \
  --log_level=-2 \
  --log_every_n=1000
```

## 🔄 Refresh Procedure

- **Autorefresh Schedule**: This import uses a fully automated refresh process configured in `manifest.json` with cron schedule `0 5 1,15 * *` (runs twice monthly, at 5:00 AM on the 1st and 15th day of each month).
- When newer CRDC releases are published by the Department of Education, `../download.py` automatically generates configurations for the new biennial periods, downloads the archives, and `run.sh` dynamically captures them for processing.
