# File dict IO user guide

`file_dict_io` provides a unified dictionary-based reader and writer interface across structured data formats used in Data Commons. It abstracts format-specific parsing, schema encoding, and serialization behind standard Python dictionary operations. See also the [File Sharder user guide](../doc/file_sharder.md).

## Overview

Callers interact with `FileDictIO` objects as Python dictionaries. Each row, node, or serialized block maps to a dictionary of string property keys and typed values.

Supported formats include:

- **CSV and TSV** (`CsvFileDictIO`): Delimited text files with header detection, RFC 4180 quote handling, and row streaming.
- **JSON and JSON Lines** (`JsonFileDictIO`): JSON object lists (`.json`) and newline-delimited JSON objects (`.jsonl`, `.ndjson`).
- **Meta Content Framework** (`McfFileDictIO`): Node-based graph definitions in standard Data Commons `.mcf` and `.tmcf` formats.
- **Apache Avro** (`AvroFileDictIO`): Binary Object Container Files with embedded schemas and block-level compression.
- **Sharded Collections** (`ShardedFileDictIO`): Virtual partitioned datasets mapped across multiple physical files using pattern syntax (`prefix@10.csv`).

## Supported formats

The table below lists the file extensions and handler classes registered in `FileDictIO`:

| Format | Extensions | Handler class | Seekable |
| :--- | :--- | :--- | :--- |
| CSV / TSV | `.csv`, `.tsv` | `CsvFileDictIO` | Yes |
| Google Sheets | Google Sheets URL | `CsvFileDictIO` | No |
| JSON Lines | `.jsonl`, `.ndjson` | `JsonFileDictIO` | Yes |
| JSON List | `.json` | `JsonFileDictIO` | No |
| MCF / TMCF | `.mcf`, `.tmcf` (default fallback) | `McfFileDictIO` | Yes |
| Apache Avro | `.avro` | `AvroFileDictIO` | Yes |
| Sharded collection | Files matching `@<N>`, `*`, `{col}`, or comma lists | `ShardedFileDictIO` | No |

## Basic usage

Open files with `open_dict_file` (or its alias `open_file_dict`). Both functions instantiate the appropriate handler class based on the file extension:

```python
from file_dict_io import open_dict_file

# Write records
with open_dict_file('output.csv', mode='w', headers=['id', 'value']) as writer:
    writer.write({'id': 'geoId/06', 'value': '39538223'})

# Read records
with open_dict_file('output.csv', mode='r') as reader:
    for record in reader:
        print(record['id'], record['value'])
```

## Format examples

### CSV and TSV

`CsvFileDictIO` handles comma-separated and tab-separated values. Column names are inferred from the first line or supplied explicitly:

```python
from file_dict_io import open_dict_file

# Writing CSV rows
with open_dict_file('places.csv', mode='w', headers=['dcid', 'name', 'pop']) as writer:
    writer.write({'dcid': 'geoId/06', 'name': 'California', 'pop': '39538223'})
    writer.write({'dcid': 'geoId/48', 'name': 'Texas', 'pop': '29145505'})

# Reading CSV rows as dicts
with open_dict_file('places.csv', mode='r') as reader:
    print('Columns:', reader.headers())
    for row in reader:
        print(f"{row['name']} has population {row['pop']}")
```

### JSON and JSON Lines

Use `.jsonl` or `.ndjson` for newline-delimited records, and `.json` for lists of JSON objects:

```python
from file_dict_io import open_dict_file

# Writing newline-delimited JSON
with open_dict_file('items.jsonl', mode='w') as writer:
    writer.write({'id': 'item1', 'tags': ['alpha', 'beta']})
    writer.write({'id': 'item2', 'tags': ['gamma']})

# Reading JSON Lines
with open_dict_file('items.jsonl', mode='r') as reader:
    for item in reader:
        print(item['id'], item['tags'])
```

### Meta Content Framework MCF

`McfFileDictIO` parses and serializes Data Commons graph nodes. Each record maps node properties to dictionary values:

```python
from file_dict_io import open_dict_file

# Writing MCF nodes
with open_dict_file('nodes.mcf', mode='w', headers=['# Generated by import']) as writer:
    writer.write({
        'Node': 'dcid:Count_Person',
        'typeOf': 'dcs:StatisticalVariable',
        'measuredProperty': 'dcs:count',
        'populationType': 'dcs:Person',
    })

# Reading MCF nodes
with open_dict_file('nodes.mcf', mode='r') as reader:
    for node in reader:
        print('Node:', node.get('Node'), 'typeOf:', node.get('typeOf'))
```

### Apache Avro

`AvroFileDictIO` reads and writes binary Apache Avro Object Container files using `fastavro`. Without an explicit `schema`, fields default to nullable strings (`['string', 'null']`); when a `schema` is provided, field values are coerced automatically to match the declared types:

```python
from file_dict_io import open_dict_file

# Writing Avro records with schema inference from headers
headers = ['id', 'count', 'active']
with open_dict_file('records.avro', mode='w', headers=headers) as writer:
    writer.write({'id': '101', 'count': 42, 'active': True})

# Reading Avro records
with open_dict_file('records.avro', mode='r') as reader:
    print('Avro fields:', reader.headers())
    for record in reader:
        print(record)
```

### Sharded collections

`ShardedFileDictIO` exposes multiple physical files as a single logical stream. Use `@<N>` syntax to split writes into `N` shards, or to read from an existing sharded set:

```python
from file_dict_io import ShardedFileDictIO

# Write 1000 records partitioned across 4 CSV shards
with ShardedFileDictIO('output@4.csv', mode='w', config={'shard_key': 'geoId'}) as writer:
    for i in range(1000):
        writer.write({'geoId': f'geoId/{i:04d}', 'value': str(i * 10)})

# Read all records across all 4 shards transparently
with ShardedFileDictIO('output@4.csv', mode='r') as reader:
    total_rows = sum(1 for _ in reader)
    print(f'Read {total_rows} rows from {len(reader.files())} shards.')
```

## Parallel reading with seek and offsets

For large datasets, multiple worker threads can process separate segments of a single file in parallel without prior splitting.

Pass `start_offset` and `end_offset` to `open_dict_file`, or call `seek(offset)` directly on an open reader:

```python
import os
from concurrent.futures import ThreadPoolExecutor
from file_dict_io import open_dict_file

def read_chunk(filename, start, end):
    records = []
    with open_dict_file(filename, mode='r', start_offset=start, end_offset=end) as reader:
        for record in reader:
            records.append(record)
    return records

file_path = 'large_data.csv'
file_size = os.path.getsize(file_path)
num_workers = 4
chunk_size = file_size // num_workers

tasks = []
for i in range(num_workers):
    start = i * chunk_size
    end = (i + 1) * chunk_size if i < num_workers - 1 else None
    tasks.append((start, end))

with ThreadPoolExecutor(max_workers=num_workers) as executor:
    results = executor.map(lambda t: read_chunk(file_path, t[0], t[1]), tasks)

all_records = [rec for chunk in results for rec in chunk]
print(f'Read {len(all_records)} records in parallel.')
```

## Format seek mechanics and caveats

Each format handler implements format-specific seek mechanics:

- **CSV / TSV**: The reader parses the header row at offset 0 before seeking. When seeking past the header, the reader scans raw newline boundaries on the underlying binary buffer so UTF-8 multi-byte characters and BOM headers never fail decoding, then starts cleanly at the next row boundary. Do not byte-chunk CSV files whose quoted field values contain unescaped raw newlines.
- **JSON Lines**: When seeking to an offset greater than 0, the reader skips to the end of the current line and begins parsing at the start of the subsequent JSON object.
- **MCF**: MCF records span multiple lines. Seeking searches forward for an unindented line starting with `Node:`. Comments and blank lines preceding the node are bypassed.
- **Apache Avro**: Avro container files are partitioned into sync blocks. The reader parses the schema and 16-byte random sync marker at offset 0, then seeks forward to the next sync marker boundary at or after the requested offset.
- **Sharded collections**: `ShardedFileDictIO` raises `UnsupportedOperation` on `seek()`, `tell()`, and non-zero offsets because sharded datasets are collections of separate files partitioned by file.

## Boundary behavior

- **`start_offset >= file_size`**: Iteration immediately raises `StopIteration`; `read()` returns `None`; `readlines()` returns `[]`.
- **`end_offset >= file_size`**: The reader streams all records until physical EOF and stops normally.
- **`start_offset >= end_offset`**: The reader returns 0 records immediately.
- **Write mode `seek()`**: Calling `seek()` on a file opened with `mode='w'` raises `io.UnsupportedOperation`.
- **Sharded collections**: Calling `seek()`, `tell()`, or passing non-zero offsets to `ShardedFileDictIO` raises `io.UnsupportedOperation`.

## Interface reference

The table below summarizes primary methods available on `FileDictIO` instances:

| Method | Return type | Description |
| :--- | :--- | :--- |
| `read()` / `next()` | `dict \| None` | Returns the next record, or `None` at EOF / `end_offset`. |
| `readlines()` | `list[dict]` | Reads and returns all remaining records until EOF / `end_offset`. |
| `write(record)` | `int` | Writes a single dictionary record or a list of records. |
| `seek(offset)` | `int` | Seeks to the nearest record boundary starting at or after `offset`. |
| `tell()` | `int` | Returns current byte position of the underlying file handle. |
| `headers()` | `list[str]` | Returns active column headers, field names, or MCF comments. |
| `set_headers(headers)` | `None` | Sets column headers for writing. |
| `start_offset()` | `int` | Returns configured start offset. |
| `end_offset()` | `int \| None` | Returns configured end offset. |
| `current_record_index()` | `int` | Returns 1-based count of records read or written. |
| `close()` | `None` | Flushes buffers and closes underlying file descriptors. |
