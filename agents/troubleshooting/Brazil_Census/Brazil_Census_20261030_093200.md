## 1. Executive Summary & Impact
* **Incident Description**: During the migration and consolidation of the legacy 16 Brazil Census import scripts into 7 standardized sub-imports (`Brazil_Census_*`), Cloud Batch execution in `datcom-infosys-dev` encountered data accuracy and validation failures:
  1. `Brazil_Census_Total_Population`: SIDRA Table 9514 was queried with `/c287/0` instead of `/c287/100362` (`Total` age), returning an unnamed aggregate row that summed overlapping age categories and inflated 2022 `Count_Person_Male` / `Count_Person_Female` by 3x (`611,562,719` total).
  2. `Brazil_Census_Education`: Substring matching on SIDRA Table 1972 `NivelEnsino` categories combined with `keep="last"` deduplication caused unmatched 2010 subcategories (`Especialização de nível superior`, `D5C=7910`) to overwrite `Total` (`Count_Student` dropped from `59,565,188` to `666,613`), and `load_municipal_mapping()` lacked a GCS fallback for `muncial_state_brazil_mapping.json`.
  3. `Brazil_Census_Literacy` & `Brazil_Census_Population_By_Residence`: Missing GCS fallbacks in `parse_2000_literacy_files()` and 1991 `POPS91*.XLS` / `Brazil_Place_Mapping_1991.json` loaders caused 32%–37% record deletions in ephemeral Cloud Batch containers.
  4. `Brazil_Census_Population_By_Race` & `Brazil_Census_Population_By_Religion`: Removing `Cor:Total` / `Religiao:Total` from PVMaps dropped 1940 `Count_Person` baselines, while 2022 SIDRA Table 9537 reported religion for population aged 10+ years (`176,600,150`).
* **Impact**: Cloud Batch staging runs failed `check_deleted_records_percent`, `check_max_date_freshness`, `check_max_date_consistent`, and `check_num_places_consistent` checks, and `latest_version.txt` was not promoted in staging.

## 2. Root Cause Analysis
1. **SIDRA Classification Code & Category Mapping Bugs**:
   - In SIDRA Table 9514, classification `c287` (`Idade`) uses code `100362` for `"Total"`, whereas `/c287/0` returns an aggregate across all overlapping age brackets.
   - In SIDRA Table 1972 (`/c11798/all`), 19 education-level categories are returned per place/year; initializing `nivel = "Total"` and matching via loose substrings caused unmapped subcategories to default to `"Total"` and overwrite the true total during `drop_duplicates(..., keep="last")`.
2. **Missing GCS Fallbacks for Historical Raw Files**:
   - Ephemeral Cloud Batch containers do not contain local `scratch/` directories. Loaders for year-2000 municipal education (`muncial_state_brazil_mapping.json`), year-2000 municipal literacy (`Brazil_2000_literacy_input/*.xls`), and 1991 residence (`Brazil_Place_Mapping_1991.json`, `POPS91*.XLS`) only checked local filesystem paths.
3. **Multi-Vintage Cohort Scoping in `validation_config.json`**:
   - Historical StatVar cohorts discontinued by IBGE in later censuses (e.g., 1991 single-year age brackets, 2000 `Count_Student_BrazilPreVestibular`, 2010 `Count_Student_AlphabetizationClass`, 2000/2010 literacy rates) have different `MaxDate` and `NumPlaces` than active 2010/2022 series, requiring cohort-scoped validation rules.

## 3. Debugging Trail & Evidence
1. **Batch Execution & Validation Inspection**:
   - Inspected `validation_output.csv` and `summary_report.csv` across all 7 sub-imports in `gs://datcom-import-test/statvar_imports/brazil_census/`.
   - Identified 3x inflation in `Brazil_Census_Total_Population` (`296,783,991` Male, `314,778,728` Female), `Count_Student` overwrite in `Brazil_Census_Education` (`666,613`), and 32%–37% deleted records in Education, Literacy, and Residence.
2. **Codebase Audit & Correction**:
   - Fixed `TABLE_9514_API_URL` in `brazil_total_population/download.py` to use `/c287/100362/`.
   - Replaced substring `NivelEnsino` matching in `brazil_education/download.py` with exact `D5C` category code mapping (`0`, `95301`–`95308`, `107454`, `7904`–`7912`), summing `Mestrado` + `Doutorado` into `Pós-graduação` and skipping unmapped subcategories.
   - Added GCS fallbacks (`gs://unresolved_mcf/country/brazil/...`) to `brazil_education/download.py`, `brazil_literacy/download.py`, and `brazil_population_by_residence/download.py`.
   - Restored `Cor:Total` and `Religiao:Total` in Race/Religion PVMaps while skipping 2022 `Total` (`10+` universe) in `brazil_population_by_religion/download.py`.
   - Scoped `validation_config.json` rules by historical vs active StatVar cohorts and restricted `manifest.json` `"node_mcf"` globs to `*_stat_vars.mcf`.

## 4. CI/CD & Testing Gap Analysis
* **Why Unit Tests Did Not Catch It**:
  - `download_test.py` files lacked `__init__.py` package markers for `unittest discover` and collided on `from download import ...` in `sys.modules`.
  - Mock payloads in unit tests only included 2 rows and did not test multi-category SIDRA Table 1972 payloads or ephemeral container execution without local `scratch/` files.

## 5. Fix Applied & Verification
* **PR #2343 & CL 1009801469 Changes**:
  - Updated all 7 `download.py`, `download_test.py`, `validation_config.json`, `manifest.json`, `README.md`, and `test_data/` fixtures in PR #2343.
  - Updated `Brazil_Census.textproto` (8 explicit `table` blocks pairing each CSV with its TMCF) and `Brazil_Census.mcf` in CL 1009801469.
  - Verified all 35 hermetic unit tests pass via `python3 -m unittest discover -v -s statvar_imports/brazil_census -p '*_test.py'`.

## 6. Long-Term Prevention & Recommendations
* **Exact SIDRA Category Code Mapping**: Always filter and map IBGE SIDRA API responses by `D*C` classification code rather than substring matching on Portuguese category labels.
* **Hermetic Container & `unittest discover` Verification**: Ensure all sub-import directories include `__init__.py` and load modules via isolated specs in `download_test.py`, with all GCS fallbacks tested in clean container environments.
